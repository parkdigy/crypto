# npm 패키지 개발

[저장소 지침](../../../AGENTS.md)과 [프로젝트 구조](../../../docs/agents/project.md)를 읽고 현재 `git status --short`, 관련 구현·테스트·설정을 확인한다. 기존 작업을 보존하며 요청 범위와 검증 방법을 정한다.

## 구현 시 확인

- `base64.encode`/`decode`는 UTF-8 문자열을 변환한다. `md5`, `sha1`, `sha256`은 문자열을 해시하며 SHA 함수는 `BinaryToTextEncoding`을 받고 기본값은 `hex`다. 동작을 바꾸기 전 기존 입력·출력과 호환성을 확인한다.
- API를 변경하면 `src/index.ts`의 이름 있는 내보내기와 기본 객체를 함께 살펴보고, 공개 타입·README·예제에 필요한 변경을 반영한다. 타입만 내보낼 때는 `export type`을 사용한다.
- 관련 테스트는 실제 공개 API를 호출한다. 변경에 맞춰 ASCII와 한글·이모지, SHA 출력 인코딩, 빈 입력 또는 오류 등 의미 있는 사례를 선택한다. 현재 테스트는 소스 진입점을 사용하므로 설치 패키지 검증을 대신하지 않는다.
- `base-64`, `md5`, `sha.js`는 peer dependency이고 `utf8`은 번들에 포함된다. 의존성이나 번들 설정을 바꾸면 소비자 설치 책임과 결과물을 확인한다.
- `dist/`는 직접 수정하지 않는다. 빌드가 추적 중인 산출물을 삭제하고 재생성하므로 먼저 기존 변경을 보존한다.

## 검증과 보고

`AGENTS.md`의 타입 검사·lint·테스트를 실행하고, 빌드나 진입점 변경에는 빌드를 추가한다. 배포 설정 변경 시 `npm pack --dry-run`과 실제 설치 소비자의 ESM·CommonJS 로딩 및 타입 해석을 확인한다. Watchman 오류로 표준 빌드가 막히면 지침에 명시된 대체 검증을 수행하고 결과를 구분한다.

마지막으로 diff에서 공개 API 누락, 생성물 및 기존 변경 훼손 여부를 확인한다. 변경 내용과 검증별 결과, 실패 원인이나 미확인 사항을 한글로 보고한다. 여러 세션에 걸치거나 인계가 필요한 경우에만 [작업 기록 양식](templates/task.md)을 `_workspace/<작업명>/task.md`로 복사해 사용한다.
